# 拓扑与 Raft 控制面第一轮实验

本轮实现隔离实验，不修改生产前后端。设计来源是客户端音频拓扑 RFC 与 Hamok 可行性探索；候选参数不升级为产品约束。交付目标是可复现的规划基线、原生 Hamok 浏览器复制与分区反例，以及是否允许继续强一致集成的结论。

## 实现范围与验收

实验放在 `experiments/hamok-topology/`，使用独立 package.json 与 lockfile，固定 `hamok@2.6.0`，采用项目同代 Vite 8 与 TypeScript 工具链。生产依赖、信令协议、音频播放不变。

纯规划器接收人工非负安全整数有向代价与成员集合，按每个源生成完整 parents 树。Dijkstra 作为无容量约束的实验基线，固定排序与等代价规则，零权边无环；缺边不补齐，不可达时返回 direct 意图，溢出明确拒绝。测试覆盖方向性、乱序确定性、零权环、非法输入和不可达。不把该算法当作最终容量受限产品策略。

Hamok 实验记录真实源码中的投票集合修改路径、提交门槛、Map 应用事件和快照语义。每个节点隔离在独立 Chromium context 中，测试协调器注入相同 roomEpoch 与初始投票名单，仅负责引导与消息故障注入；不改变原生库、不把名单注入声称为固定配置保证。浏览器兼容层只添加实际需要的 events、Buffer 与 nextTick，并验证 protobuf 消息往返。

故障脚本至少覆盖稳定三节点复制、双节点断开、三节点 2+1、四节点 2+2、三节点 1+1+1 以及旧 leader 隔离。分区持续时间超过实际配置的 election、peer heartbeat 和相关 unsynced 处理窗口。记录版本、seed、代次、初始与实际投票集合、term、leader、可取得的提交位置、Map 内容与事件时间线。分区两侧提出不同的同一修订内容，区分复制应用与本地写请求；异常与未知结果不能算通过。

测试提供两种结果：实验机制正常运行的断言，以及强一致安全闸门的独立结果。原生行为允许作为被记录的反例，但安全闸门失败必须在报告中明确阻止强一致拓扑发布，提供非零退出的 gate 命令，不能以最终收敛或冲突检测代替安全。

报告区分实际验证、源码推断与未知，给出继续／受限继续／停止结论，并附运行命令、事件样例和后续路线。若安全闸门失败，本轮止于证据与纯规划器，不实现模型 A/B 集成、固定配置 fork、DataChannel 或音频中继；这些必须另行确定修改范围。若未发现反例，仍不据有限测试宣称生产安全，本轮同样不扩大范围。
